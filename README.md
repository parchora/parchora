# Parchora

> A cross-platform desktop "capture → organize" workbench — macOS edition
> Rust + GPUI (gpui-fast) · Local-first · No backend / No accounts

Parchora is a persistent menu-bar desktop application. It watches the clipboard continuously, automatically persists
captured content into a local store, classifies it by type, and lets you summon a panel from the screen edge at any
time to complete the "pick up → organize → retrieve" loop. All data stays on the machine (SQLite + plain `.md`
files); the app never reaches the network, has no accounts, and has no upload path.

> **Current status**: the application is mid-implementation. `parchora-app` currently acts as a "demonstration host"
> that carries all window assembly and the full data path. The view layer (19 pages + 5 dialogs) has been
> implemented page-by-page against the HTML design mockups; most pages still render demonstration data.

## Features

### Clipboard Pick-up (capture)

- **0.5 s polling** of the clipboard `changeCount`; a change triggers a sample
- **8-way content classification chain** (fixed priority): `color` → `image` → `fileURL` → `url` (re-classified when
  plain text carries both a scheme and a host) → `html` → `richText` → `plainText`, falling back to `unknown`.
  Privacy-marker rejection is carried by a dedicated function and runs *before* the chain.
- **100% privacy rejection**: pasteboards marked Transient / Concealed / AutoGenerated are rejected outright and
  never persisted
- **Frontmost-app exclusion**: source applications can be excluded by bundleId
- **10 s SHA-256 deduplication**: identical content is stored at most once per 10-second window
- **Self-write skip**: content this process wrote to the clipboard is skipped on read-back (full-text comparison
  within a 1.5 s registration window)

### Promise-based Clipboard Queue

- Queue entries are mounted onto the system clipboard as a "promise"; an external app requesting the data is
  treated as a paste signal
- **350 ms settlement window** and **300 ms activation window** (distinguishing a *probe* from a *real consumption*)
- FIFO / LIFO consumption-order modes
- Dual-channel hinting ("bounce" + system notification) with a configurable 1–20 s throttle interval

### Edge-Triggered Panel

- **7 trigger positions**: bottom / left / right / top-left / top-right / bottom-left / bottom-right (default: right)
- A **12 pt hot zone** along the usable-area edge (`NSScreen` `visibleFrame`); corner positions use a 4 px square
- **Automatic side switch on Dock conflict** (left→right, right→left, bottom→right)
- Single-instance protection (`flock`); a duplicate launch exits immediately

### Content Organization

- **Collections** (projects / pinboard), **Tasks** (5 statuses / 5 priorities / 5 schedule buckets), **Labels**
  (7 colors)
- **Pick-up history**, **Trash**, **Notes** (plain `.md` files, where the filename is the title)
- Clipboard history retention duration, validity duration, item-count cap, and the monitoring switch are all
  configurable

### Reading and Editing

- Dual engine: Markdown editor (`zorite-editor`) and read-only rendering view (`zorite-markdown`)
- The content detail window (Peek) supports image preview, Markdown rendering, and hand-off to the editor
- Image thumbnail pipeline (longest edge 320 px)

### Interface

- The "Parchment Ink" design-token system, with a single source of truth (`parchora-ui::tokens`; a 17-color palette
  per `DESIGN.md`, materialized as 19 Rust constants including aliases)
- **6 resolution/scale tiers** (Low / Hd / Qhd / Uqhd / FourK / U4K) × an **11-step type scale**, with one profile
  per display and automatic re-tiering when moving across displays
- 24 inline Lucide linear icons (embedded at build time via `include_bytes!`, zero added dependencies)

## Installation and Usage

### 1. Obtain the source

```bash
git clone https://github.com/<org>/<repo>.git
cd <repo>/app
```

### 2. Build

```bash
# Debug build → target/debug/parchora-app
cargo build

# Release build (lto = "thin" · codegen-units = 1) → target/release/parchora-app
cargo build --release
```

### 3. Run

```bash
# Run the binary directly
cargo run -p parchora-app

# Or run it after building
./target/debug/parchora-app
```

### 4. Command-line arguments

The first positional argument of `parchora-app` selects the launch form; in most forms the second argument is the
trigger position.

> **Note on position tokens**: the accepted trigger-position tokens are Chinese literals in the source
> (`bottom` / `left` / `right` / `top-left` / `top-right` / `bottom-left` / `bottom-right`). The English glosses below are for
> readability only — the Chinese token is what must be typed.

|Command |Effect |
|---|---|
|`parchora-app` |Main panel (default; trigger position taken from the settings profile, or right when unset) |
|`parchora-app demo bottom` |Main panel with an explicit trigger position (7 options: bottom, left, right, top-left, top-right, bottom-left, bottom-right) |
|`parchora-app --peek bottom` |Content detail (Peek) window |
|`parchora-app --page editor\|conflict\|ext\|picker` |Context-free page demonstration windows (editor / conflict / external conflict / picker) |
|`parchora-app --settings` |Settings window |
|`parchora-app --menu` |Menu-bar menu demonstration window |
|`parchora-app --root` |Root picker demonstration window |

```bash
# Examples
cargo run -p parchora-app -- demo top-left
cargo run -p parchora-app -- --page editor
```

### 5. Operating the app

The app runs with the **Accessory (**`LSUIElement`) policy: **no Dock icon**, permanently resident in the menu bar.

- Move the pointer to the hot zone at the edge of the screen's usable area → the main panel docks and reveals
- Click the menu-bar icon → in docked mode, toggles the main panel
- The menu-bar dropdown provides "Reveal main panel" and "Quit"

## Configuration

### Configuration file location

```text
$HOME/.parchora/
├── data/
│   ├── parchora-settings.env   # Settings profile (line-based key=value)
│   └── parchora.db             # SQLite structured data (SQLite manages -wal / -shm)
└── files/                      # Knowledge content (plain .md files)
```

When `$HOME` is unavailable the app falls back to the relative path `.parchora` (a testing / sandbox tolerance).

### Settings profile keys (`data/parchora-settings.env`)

Line-based `key=value`. Any change is written to disk immediately (atomic `tmp + rename`). Each key fails
independently — an invalid value only reverts that key to its default and leaves the rest untouched.

|Key |Accepted values |Default |Description |
|---|---|---|---|
|`trigger` |`bottom` / `left` / `right` / `top-left` / `top-right` / `bottom-left` / `bottom-right` |Trigger position |   |
|`clip_retention_days` |Integer ≥ 1 |`1` |Clipboard history retention, in days |
|`clip_valid_min` |Integer ≥ 1 (default `24*60` = 1440) |`1440` |Validity duration of a single captured item, in minutes |
|`capture_enabled` |`true` / `false` |`true` |Master switch for clipboard monitoring |
|`capture_limit` |`100` / `500` / `1000` / `5000` / `0` |`500` |History cap tier (`0` = unlimited) |
|`queue_notify_interval` |Integer 1–20 |`5` |Queue hint throttle interval, in seconds |
|`queue_order` |`fifo` / `lifo` |`fifo` |Queue consumption order |
|`capture_exclude_apps` |Comma-separated bundleIds |empty |Frontmost applications to exclude |

Example:

```ini
trigger=右侧
clip_valid_min=1440
clip_retention_days=1
capture_enabled=true
capture_limit=500
queue_notify_interval=5
queue_order=fifo
capture_exclude_apps=com.apple.Terminal,com.googlecode.iterm2
```

> **Legacy keys** (always ignored on read, never written back): `peek_delay=`, `clip_survive_min=`.

### Storage roots

|Purpose |Path |
|---|---|
|Application data root |`$HOME/.parchora` |
|SQLite database |`$HOME/.parchora/data/parchora.db` |
|Knowledge content root |`$HOME/.parchora/files` |
|Note trash |The `.trash` directory alongside the files root |
|Single-instance lock |`parchora-app.lock` in the temp directory (`flock`, released automatically on process exit) |

### Environment variables

The application recognizes only the following environment variables at runtime. All of them are **frame-telemetry**
related and take effect only in builds carrying the `frame-profiler` feature:

|Variable |Default |Description |
|---|---|---|
|`PARCHORA_FRAME_TELEMETRY` |unset |Set to `1` to activate frame telemetry; any other value keeps it off |
|`PARCHORA_FRAME_TELEMETRY_WARMUP_S` |`2.0` |Warm-up duration in seconds (must be > 0) |
|`PARCHORA_FRAME_TELEMETRY_DURATION_S` |`8.0` |Measurement duration in seconds (must be > 0) |
|`PARCHORA_FRAME_TELEMETRY_INVALIDATE_HZ` |`60.0` |Forced-invalidation drive frequency; an explicit `0` selects **passive observation mode** (no injected drive ticks, natural frames only) |
|`PARCHORA_FRAME_TELEMETRY_SCENARIO` |none |Scenario: `reveal` / `reveal-close` / `scroll` (an unknown value is treated as "no scenario" and is disclosed on stderr) |

> Telemetry results are written to stderr with the `[parchora-frame]` prefix, ending with a single-line JSON summary.

## Core Modules

### Dependency direction (enforced at compile time)

```text
                        parchora-app
          ┌──────────┬──────┬───────┬──────────┬────────────┐
          ▼          ▼      ▼       ▼          ▼            ▼
   parchora-ui   core    db     files    capture      platform
          │          ▲      ▲                ▲            ▲
          │          └──────┴────────────────┴────────────┘
          │        (db / capture / platform → core, one-way)
          │
          └─► gpui-fast · gpui-component · zorite-editor · zorite-markdown

   parchora-core  ──► serde · uuid        (no platform dependencies)
   parchora-files ──► (no dependencies)
```

Key points:

- `parchora-ui` **does not depend on** `parchora-core` (the view layer owns its own presentation models)
- `parchora-core` is the single shared lower layer, referenced one-way by `db` / `capture` / `platform`

Two boundary invariants enforced by the compiler:

1. `parchora-core` types **contain no persistence types** (pure domain models)
2. The `parchora-db` public API **contains no** `.md` body text; the `parchora-files` public API **contains no DB
   types**

### `parchora-db` — SQLite storage (1804 lines)

- **Schema v3**: 14 tables + 6 indexes

## Key Workflows

### Clipboard capture chain

```text
0.5 s poll tick
  │
  ├─ change_count identical to baseline ──→ done (no change)
  │
  ├─ board sample → BoardContent
  │     ├─ Empty      → done (an empty copy produces no entry)
  │     ├─ Rejected   → done (100% rejection on the three privacy markers)
  │     └─ Snapshots  → continue
  │
  ├─ frontmost app matches capture_exclude_apps ──→ done
  │
  ├─ core::classify 8-way chain ──→ ContentType
  │
  ├─ self-write check (clipstamp: equal within the 1.5 s window) ──→ done
  │
  ├─ SHA-256 → content_hash
  │
  ├─ DedupeLru 10 s dedupe ──hit──→ done
  │
  └─ persist to the clips table (+ write image payloads to the blobs directory)
        └─ beyond the cap tier → prune by retention duration / validity duration
```

### Promise queue chain

```text
place ──→ Placed{entry} ──demand (an external app requests it)──→ Settling{settle_at, replace}
                                                      │
                                        ┌─────────────┴─────────────┐
                                  [not a probe]                  [probe]
                              consumption: the entry        the promise is re-asserted
                              flows out; the host           (the board is replaced with
                              auto-lists its successor       the same entry as a new
                              on the next tick)              promise — not consumed,
                                                            order unchanged, no event)
```

### Edge-reveal chain

```text
0.05 s poll of cursor_position
  │
  ├─ inside a trigger hot zone (12 pt edge family / 4 px corner family)?
  │     ├─ no  → check the out-of-bounds buffer band / seam grace band → collapse if needed
  │     └─ yes → filter through the exclusion band (50 pt)
  │              ├─ excluded → no response
  │              └─ passed   → reveal the main panel (dock position + Dock conflict resolution)
  │
  └─ while the panel is present: exit → buffer-band hold → two-tick confirmation → collapse
```

## Run and Deploy

### Packaging into a `.app`

```bash
# Default: release profile + the default brand source at ../<brand-source>.png
bash tools/package_app.sh

# Debug profile (symbols retained, for lldb)
bash tools/package_app.sh debug

# Explicit brand source (.png or .svg)
bash tools/package_app.sh release ../path/to/logo.png
```

**Packaging chain** (steps `[1/6]`–`[6/6]` inside the script):

1. `cargo build -p parchora-app` (release / debug)
2. Generate a 1024 × 1024 base PNG (a PNG source is padded to a square with transparency by `pad_logo.swift`; an SVG
   source is rendered by `render_logo.swift`)
3. `sips` downsamples the full iconset size set → `iconutil` composes `AppIcon.icns`
4. Assembles `dist/Parchora.app` (the release profile is `strip`ped)
5. `plutil -lint` validates `Info.plist`
6. `codesign --force --sign -` ad-hoc signature → `codesign --verify --strict`

**Key entries in the generated** `Info.plist`:

|Key |Value |
|---|---|
|`CFBundleIdentifier` |`com.parchora.app` |
|`CFBundleName` |`Parchora` |
|`CFBundleShortVersionString` / `CFBundleVersion` |Taken from `Cargo.toml` → `workspace.package.version` |
|`LSUIElement` |`true` (no Dock icon; permanently resident in the menu bar) |
|`NSHighResolutionCapable` |`true` |
|`LSMinimumSystemVersion` |`10.15.7` |

### Auxiliary scripts

```bash
# SVG → PNG (512 px by default; the iconset base needs 1024)
swift tools/render_logo.swift input.svg output.png 1024

# PNG → square transparent-padded PNG
swift tools/pad_logo.swift input.png output.png 1024

# Export the app icon of a running instance (diagnostics)
swift tools/probe_icon.swift <pid> out.png
```

### Deployment notes

- The artifact carries an **ad-hoc signature** (`codesign --sign -`), not a Developer ID signature; it is **not
  notarized** — the source contains no notarization implementation
- The source contains **no** auto-updater, network client, or account system (there are no HTTP dependencies under
  `crates/`)

## Contributing

### Behavioral contract

The project's behavioral contract and product documentation live in the **product repository root** — the directory
one level above this engineering repository:

```text
../AGENTS.md      # Behavioral contract (the single governance document)
../docs/          # Requirements / specifications / design / decision records
```

Within `docs/`, the capability-domain `spec.md` files are the **sole authority on behavioral rules**, and the
requirement-engineering directory provides the "requirement → design → test → traceability" index. Before making a
change, read the corresponding `REQ-*` / `SCN-*` entries.

### Coding conventions

- Commit messages follow **conventional commits**: a short imperative subject, a single concern, and an issue
  reference
- Every implementation should name its **specification anchor** (`REQ-*` / `SCN-*` / `DEC-*`) and the crate's
  **boundary invariant** in a comment
- Keep the dependency direction one-way: `core` ← `db` / `capture` / `platform`; `ui` does not depend on `core`; the
  `db` API contains no `.md` body text and the `files` API contains no DB types
- `vendor/` is a read-only baseline and **must not be edited directly**; when a change is needed, validate it in
  `spikes/` and bring it back as a patch

### Pre-commit self-check

```bash
cargo build             # compiles
cargo test              # all tests pass
cargo build --release   # the release profile compiles (LTO may be slow)
```

- Review the blast radius and regression results before changing anything
- Changes touching windows / the daemon / storage should include a real-machine regression record
- **Do not commit** build or run artifacts: `target/` · `dist/` · `e2e/evidence/` · `e2e/report*.json` ·
  `e2e/REPORT.md` · `vendor/*/target/` · `spikes/**/target/` (all listed in `.gitignore`)

### Repository status

- This engineering repository has **no** CI configuration (no `.github/` directory) and **no** `Makefile` /
  `justfile`
- Change records are carried by the closing report or the commit message (see the behavioral contract, §11)
